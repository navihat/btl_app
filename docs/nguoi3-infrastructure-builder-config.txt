1. Ý TƯỞNG VÀ LÝ DO LỰA CHỌN
--------------------------------------------------------------

Người 3 chịu trách nhiệm 3 nhóm công việc:
  (A) Lớp Infrastructure: Hiện thực hóa repository bằng JSON file
  (B) Builder pattern: Xây dựng Exam từng bước có validate
  (C) Config & wiring: Cấu hình toàn bộ project + kết nối các tầng

Tại sao chọn JSON thay vì SQLite?
  - MVP nhanh: không cần cài thêm driver, không migration.
  - Dễ debug: mở file bằng text editor là thấy data ngay.
  - Đủ dùng cho quy mô ngân hàng câu hỏi vài trăm câu.
  - Nếu sau này cần SQLite: chỉ tạo SqliteQuestionRepository mới
    implements IQuestionRepository → không sửa gì ở service/domain.

Tại sao chọn Builder cho tạo Exam?
  Vấn đề: Exam có nhiều field (title, description, duration,
  difficulty) và cần validate trước khi tạo. Nếu dùng
  constructor thông thường:
    new Exam(title, description, duration, difficulty)
  → Khó đọc (4 tham số vị trí), dễ nhầm thứ tự.
  → Không thể enforce validate trước khi object được tạo.

  Builder Pattern giải quyết:
    examBuilder
      .setTitle('Đề giữa kỳ')
      .setDescription('Chương 1-3')
      .setDuration(45)
      .setDifficulty('medium')
      .build()  ← throw ngay tại đây nếu thiếu field bắt buộc

  build() chịu trách nhiệm validate toàn bộ, đảm bảo Exam
  không bao giờ được tạo ra trong trạng thái không hợp lệ.

Tại sao dùng serviceFactory.ts?
  Electron main process cần khởi tạo tất cả dependencies
  (repo, factory, builder, strategy, subject) rồi inject vào
  service. serviceFactory.ts là nơi "wire" (nối dây) duy nhất,
  dùng Singleton pattern đơn giản để tránh tạo nhiều instance.

4. CHI TIẾT TỪNG FILE
--------------------------------------------------------------

---- src/infrastructure/JsonQuestionRepository.ts ----

Implements IQuestionRepository bằng cách đọc/ghi file JSON.

Constructor:
  constructor(private readonly filePath: string)
  → Gọi ensureFile() ngay khi tạo instance

ensureFile():
  - Tạo thư mục nếu chưa có (mkdirSync recursive)
  - Tạo file với { questions: [] } nếu chưa có
  → Đảm bảo app không crash lần đầu chạy

readStore():
  readFileSync(filePath, 'utf-8') → JSON.parse()

writeStore(store):
  JSON.stringify(store, null, 2) → writeFileSync()
  (indent 2 để file dễ đọc)

findAll(filter?):
  - Đọc toàn bộ câu hỏi
  - Nếu filter.difficulty: lọc theo difficulty
  - Nếu filter.topic: lọc includes() case-insensitive

findById(id):
  - Array.find() → null nếu không có

save(question):
  - push vào mảng → writeStore

update(question):
  - findIndex → throw nếu -1
  - store.questions[idx] = question → writeStore

delete(id):
  - filter() loại bỏ → writeStore

SRP: Class này KHÔNG chứa bất kỳ business logic nào.
Nếu cần đổi sang SQLite: tạo SqliteQuestionRepository
implements IQuestionRepository, không sửa gì ở service.


---- src/infrastructure/JsonExamRepository.ts ----

Tương tự JsonQuestionRepository nhưng cho Exam.
Cấu trúc file: { "exams": [...] }
Không có filter trong findAll() (lấy tất cả đề thi).


---- src/patterns/builder/IExamBuilder.ts ----

  interface IExamBuilder {
    setTitle(title: string): this
    setDescription(description: string): this
    setDuration(minutes: number): this
    setDifficulty(difficulty: Difficulty | 'mixed'): this
    build(): Exam
    reset(): this
  }

Trả về this trong mỗi setter → cho phép method chaining.
ExamService phụ thuộc vào interface này (DIP),
không phụ thuộc vào ExamBuilder cụ thể.


---- src/patterns/builder/ExamBuilder.ts ----

Builder Pattern – Concrete Builder.

Private state:
  title = ''
  description = ''
  duration = 0
  difficulty: Difficulty | 'mixed' = 'mixed'

Mỗi setter: this.xxx = value; return this
→ Cho phép: builder.setTitle('A').setDuration(45).build()

build():
  Validate:
    - title rỗng → throw 'Tên đề thi không được để trống.'
    - duration <= 0 → throw 'Thời gian làm bài phải lớn hơn 0 phút.'
  Tạo Exam:
    { id: uuidv4(), title, description, duration, difficulty,
      questionIds: [],   ← luôn rỗng khi mới tạo
      createdAt: new Date().toISOString() }
  Gọi reset() → xóa state nội bộ để tái sử dụng builder
  Return exam

Tại sao gọi reset() sau build()?
  Tránh state cũ rò rỉ sang lần gọi build() tiếp theo.
  Ví dụ không có reset():
    builder.setTitle('Đề A').setDuration(30).build()
    builder.setDuration(60).build()  ← title vẫn là 'Đề A' !
  Với reset(): lần 2 sẽ throw vì title rỗng → đúng hành vi.


---- src/main/serviceFactory.ts ----

Singleton factory để khởi tạo services một lần duy nhất.

getDataPath():
  - Nếu app.isPackaged (bản build cuối): lấy folder cạnh .exe
  - Nếu dev mode: lấy process.cwd()/data (thư mục project)

getQuestionService():
  if (!questionServiceInstance)
    repo = new JsonQuestionRepository(getDataPath() + '/questions.json')
    factory = new QuestionFactory()
    questionServiceInstance = new QuestionService(repo, factory)
  return questionServiceInstance

getExamService():
  if (!examServiceInstance)
    examRepo = new JsonExamRepository(getDataPath() + '/exams.json')
    questionRepo = new JsonQuestionRepository(getDataPath() + '/questions.json')
    builder = new ExamBuilder()
    strategy = new ManualSelectionStrategy()
    subject = new ExamSubject()
    examServiceInstance = new ExamService(examRepo, questionRepo,
                                          builder, strategy, subject)
  return examServiceInstance

Đây là ví dụ DIP trong thực tế:
  QuestionService không biết mình đang dùng Json hay Sqlite.
  Chỉ serviceFactory biết — và đây là nơi DUY NHẤT cần thay đổi
  nếu muốn đổi storage.


---- src/main/ipc/questionHandlers.ts ----

Bridge giữa Renderer và QuestionService.

  registerQuestionHandlers():
    ipcMain.handle('question:create', async (_, dto) =>
      service.createQuestion(dto))
    ipcMain.handle('question:update', async (_, id, dto) =>
      service.updateQuestion(id, dto))
    ipcMain.handle('question:delete', async (_, id) =>
      { await service.deleteQuestion(id); return {success: true} })
    ipcMain.handle('question:list', async (_, filters?) =>
      service.listQuestions(filters))

Lý do dùng ipcMain.handle thay vì ipcMain.on:
  handle() trả về Promise → Renderer dùng invoke() nhận kết quả.
  on() là fire-and-forget, không nhận kết quả trả về.


---- src/main/ipc/examHandlers.ts ----

Bridge cho ExamService.
  'exam:create'       → service.createExam(dto)
  'exam:addQuestions' → service.addQuestions(examId, questionIds)
  'exam:delete'       → service.deleteExam(id)
  'exam:list'         → service.listExams()
  'exam:get'          → service.getExam(id)


---- src/main/index.ts ----

Electron entry point.

  app.whenReady():
    registerQuestionHandlers()   ← đăng ký tất cả IPC handlers
    registerExamHandlers()
    createWindow()               ← tạo cửa sổ chính

  createWindow():
    new BrowserWindow({
      preload: join(__dirname, '../preload/index.js')
      contextIsolation: true    ← bắt buộc để contextBridge hoạt động
      sandbox: false
    })
    
    if (ELECTRON_RENDERER_URL) loadURL(dev server)
    else                        loadFile(built HTML)

  Tại sao contextIsolation: true?
  Bảo mật: Renderer không thể truy cập trực tiếp Node.js API.
  Chỉ những gì được expose qua contextBridge mới dùng được.
