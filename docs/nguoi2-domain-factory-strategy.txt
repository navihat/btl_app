1. Ý TƯỞNG VÀ LÝ DO LỰA CHỌN
--------------------------------------------------------------

Người 2 chịu trách nhiệm lớp "domain" — trái tim của ứng dụng.
Đây là nơi chứa toàn bộ business logic (nghiệp vụ), tách biệt
hoàn toàn với việc lưu trữ (JSON file) và giao diện (React).

Tư duy thiết kế:
  Thay vì viết logic trực tiếp vào IPC handler hoặc UI,
  ta tổ chức theo tầng:

    Renderer → IPC → Service → Repository (interface)
                        ↕
                    Factory / Strategy (pattern)

Tại sao cần tầng Domain riêng?
  - Có thể unit test service/factory mà không cần chạy Electron.
  - Thay đổi cách lưu trữ (JSON → SQLite) không ảnh hưởng service.
  - Thay đổi giao diện không ảnh hưởng nghiệp vụ.

Tại sao chọn Factory Method cho câu hỏi?
  Vấn đề: Khi tạo Question, cần:
    (1) Sinh uuid cho cả question lẫn từng option
    (2) Validate đủ 4 options, content không rỗng, topic không rỗng
    (3) Gắn correctOptionId đúng với option tương ứng
  
  Nếu để QuestionService tự làm → vi phạm SRP (service vừa
  validate vừa orchestrate vừa khởi tạo object).
  → Tách ra QuestionFactory: chỉ làm 1 việc là "tạo Question hợp lệ".

Tại sao chọn Strategy cho chọn câu hỏi vào đề?
  Hiện tại chỉ có Manual (giảng viên tick thủ công), nhưng về sau
  có thể thêm:
    - RandomStrategy: chọn ngẫu nhiên theo số lượng và độ khó
    - ByTopicStrategy: chọn theo tỷ lệ từng chủ đề
  
  Nếu hard-code logic trong ExamService → vi phạm OCP (phải sửa
  service mỗi khi thêm cách chọn mới).
  → Tách ra interface IQuestionSelectionStrategy: ExamService chỉ
  gọi strategy.select(), không biết cách nào đang được dùng.

4. CHI TIẾT TỪNG FILE
--------------------------------------------------------------

---- src/domain/entities/Question.ts ----

Định nghĩa toàn bộ kiểu dữ liệu liên quan đến câu hỏi.

  enum Difficulty { Easy = 'easy', Medium = 'medium', Hard = 'hard' }

  interface QuestionOption {
    id: string      ← uuid, sinh bởi QuestionFactory
    text: string
  }

  interface Question {
    id: string           ← uuid
    content: string      ← nội dung câu hỏi
    options: QuestionOption[]   ← luôn đúng 4 phần tử
    correctOptionId: string     ← phải là id của 1 trong 4 options
    difficulty: Difficulty
    topic: string
    createdAt: string    ← ISO string
  }

  interface CreateQuestionDTO {   ← dùng khi tạo mới
    content: string
    options: { text: string }[]  ← không có id (factory sinh)
    correctOptionIndex: number   ← index 0-3
    difficulty: Difficulty
    topic: string
  }

  interface UpdateQuestionDTO {   ← dùng khi cập nhật (partial)
    content?: string
    options?: { text: string }[]
    correctOptionIndex?: number
    difficulty?: Difficulty
    topic?: string
  }

  interface QuestionFilter {      ← dùng để lọc danh sách
    difficulty?: Difficulty
    topic?: string
  }

Lý do tách DTO khỏi Entity:
  Entity có id và createdAt (do hệ thống sinh).
  DTO chỉ chứa dữ liệu từ người dùng nhập vào.
  → Không thể bị inject id giả từ client.


---- src/domain/entities/Exam.ts ----

  interface Exam {
    id: string
    title: string
    description: string
    duration: number      ← số phút
    difficulty: Difficulty | 'mixed'
    questionIds: string[] ← chỉ lưu id, không nhúng Question
    createdAt: string
  }

Tại sao chỉ lưu questionIds thay vì nhúng cả Question?
  - Tránh dữ liệu trùng lặp giữa questions.json và exams.json.
  - Khi câu hỏi bị sửa, đề thi tự động phản ánh bản mới nhất.
  - Khi cần hiển thị chi tiết đề, gọi thêm questionList() và filter.


---- src/domain/repositories/IQuestionRepository.ts ----

  interface IQuestionRepository {
    findAll(filter?: QuestionFilter): Promise<Question[]>
    findById(id: string): Promise<Question | null>
    save(question: Question): Promise<void>
    update(question: Question): Promise<void>
    delete(id: string): Promise<void>
  }

Đây là abstraction (DIP). QuestionService chỉ biết interface này,
không biết JsonQuestionRepository hay InMemoryQuestionRepository.
→ Khi test: dùng InMemoryQuestionRepository (nhanh, không cần file).
→ Khi chạy thật: dùng JsonQuestionRepository.

---- src/patterns/factory/IQuestionFactory.ts ----

  interface IQuestionFactory {
    create(data: CreateQuestionDTO): Question
  }

DIP: QuestionService phụ thuộc vào interface này,
không phụ thuộc vào QuestionFactory cụ thể.


---- src/patterns/factory/QuestionFactory.ts ----

Factory Method Pattern – Concrete Factory.

Luồng xử lý trong create():
  1. Validate content không rỗng
     → throw 'Nội dung câu hỏi không được để trống.'
  2. Validate options.length === 4
     → throw 'Câu hỏi phải có đúng 4 đáp án.'
  3. Validate từng option.text không rỗng
  4. Validate correctOptionIndex trong khoảng [0, 3]
     → throw 'Chỉ số đáp án đúng không hợp lệ.'
  5. Validate topic không rỗng
  6. Sinh uuid cho mỗi option
  7. Trả về Question object hoàn chỉnh với uuid mới

Ví dụ sử dụng:
  const factory = new QuestionFactory()
  const question = factory.create({
    content: 'Hà Nội là thủ đô của?',
    options: [
      { text: 'Việt Nam' },
      { text: 'Trung Quốc' },
      { text: 'Nhật Bản' },
      { text: 'Hàn Quốc' }
    ],
    correctOptionIndex: 0,
    difficulty: Difficulty.Easy,
    topic: 'Địa lý'
  })
  // question.id = 'uuid-xyz'
  // question.options[0].id = 'uuid-abc'
  // question.correctOptionId = 'uuid-abc'


---- src/patterns/strategy/IQuestionSelectionStrategy.ts ----

  interface SelectionCriteria {
    selectedIds: string[]
  }

  interface IQuestionSelectionStrategy {
    select(bank: Question[], criteria: SelectionCriteria): Question[]
  }

OCP: ExamService.addQuestions() chỉ gọi:
  this.selectionStrategy.select(bank, { selectedIds })
→ Không cần sửa ExamService khi thêm strategy mới.


---- src/patterns/strategy/ManualSelectionStrategy.ts ----

Concrete Strategy cho "giảng viên chọn thủ công".

Luồng:
  1. Tạo Map từ bank: id → Question (O(n) lookup)
  2. Duyệt criteria.selectedIds
  3. Mỗi id: lấy từ Map, throw nếu không tồn tại
  4. Trả về Question[] theo đúng thứ tự selectedIds

Dùng Map thay vì Array.find() vì:
  - Array.find() mỗi lần là O(n) → với 50 câu tick, tổng O(n²)
  - Map lookup là O(1) → tổng O(n)


---- src/domain/services/QuestionService.ts ----

SRP: chỉ điều phối nghiệp vụ câu hỏi.
DIP: nhận IQuestionRepository và IQuestionFactory qua constructor.

Constructor:
  constructor(
    private readonly questionRepo: IQuestionRepository,
    private readonly questionFactory: IQuestionFactory
  ) {}

Các method:
  createQuestion(dto):
    → factory.create(dto)   ← validate + tạo object
    → repo.save(question)   ← lưu vào storage
    → return question

  updateQuestion(id, dto):
    → repo.findById(id) → throw nếu không tồn tại
    → spread existing, apply từng field của dto (partial update)
    → repo.update(updated)

  deleteQuestion(id):
    → repo.findById(id) → throw nếu không tồn tại
    → repo.delete(id)

  listQuestions(filter?):
    → repo.findAll(filter)

  getQuestion(id):
    → repo.findById(id) → throw nếu null


---- src/domain/services/ExamService.ts ----

SRP: chỉ điều phối nghiệp vụ đề thi.
DIP: nhận tất cả dependencies qua constructor injection.
OCP: strategy có thể thay thế mà không sửa service.

Constructor nhận 5 dependencies:
  examRepo:          IExamRepository
  questionRepo:      IQuestionRepository
  examBuilder:       IExamBuilder
  selectionStrategy: IQuestionSelectionStrategy
  examSubject:       ExamSubject

createExam(dto):
  → examBuilder.setTitle().setDescription().setDuration()
                .setDifficulty().build()   ← Builder pattern
  → examRepo.save(exam)
  → examSubject.notify('created', exam)    ← Observer pattern
  → return exam

addQuestions(examId, questionIds[]):
  → examRepo.findById(examId) → throw nếu không tồn tại
  → Kiểm tra duplicates: questionIds ∩ exam.questionIds
    → throw nếu có câu đã tồn tại trong đề
  → questionRepo.findAll() → lấy toàn bộ bank
  → selectionStrategy.select(bank, {selectedIds})
    → throw nếu id nào không trong bank (từ Strategy)
  → Gộp questionIds cũ + mới
  → examRepo.update(updatedExam)

deleteExam(id):
  → examRepo.findById → throw nếu không tồn tại
  → examRepo.delete(id)
  → examSubject.notify('deleted', exam)

5. SOLID – GHI CHÚ CHO BÁO CÁO
--------------------------------------------------------------

SRP (Single Responsibility Principle):
  File áp dụng: QuestionService.ts
  Lý do: QuestionService chỉ có 1 lý do thay đổi là khi
  nghiệp vụ câu hỏi thay đổi. Nó không đọc/ghi file (repo làm),
  không validate/tạo object (factory làm).

  File áp dụng: QuestionFactory.ts
  Lý do: Factory chỉ có 1 lý do thay đổi là khi quy tắc
  khởi tạo Question thay đổi (thêm field, đổi validate...).

OCP (Open/Closed Principle):
  File áp dụng: IQuestionSelectionStrategy.ts
  Lý do: Muốn thêm cách chọn câu hỏi mới (Random, ByTopic)
  chỉ cần tạo class mới implements interface này, KHÔNG sửa
  ExamService.ts.

DIP (Dependency Inversion Principle):
  File áp dụng: QuestionService.ts
  Lý do: Constructor nhận IQuestionRepository (interface) thay vì
  JsonQuestionRepository (class cụ thể). Khi test, inject
  InMemoryQuestionRepository; khi chạy thật, inject JSON version.

  File áp dụng: ExamService.ts
  Lý do: Nhận IExamRepository, IQuestionRepository, IExamBuilder,
  IQuestionSelectionStrategy — toàn bộ là interface.

  [Renderer] Giảng viên điền form + bấm Lưu
       ↓

    options: [{text:'A'},{text:'B'},{text:'C'},{text:'D'}],
    correctOptionIndex: 2,
    difficulty: 'medium',
    topic: 'Vật lý'
  })
       ↓ ipcRenderer.invoke('question:create', dto)
       ↓
  [Main] questionHandlers.ts → QuestionService.createQuestion(dto)
       ↓
  QuestionFactory.create(dto):
    - Validate content, options (4), correctOptionIndex (2 hợp lệ), topic
    - Sinh uuid cho question: 'q-abc123'
    - Sinh uuid cho 4 options: 'o-1', 'o-2', 'o-3', 'o-4'
    - correctOptionId = 'o-3' (index 2)
    - Trả về Question object
       ↓
  JsonQuestionRepository.save(question):
    - Đọc data/questions.json
    - Push question mới vào mảng
    - Ghi lại file
       ↓
  [Renderer] Nhận Question object → setShowModal(false) → loadQuestions()
